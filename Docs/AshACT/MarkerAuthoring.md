# 标记系统配置与效果请求草稿

> 当前模块边界见 [配置编辑与运行模块](ConfigurationModules.md)：有效标签配置可独立通过作者期校验；运行编译的拒绝与 Host 集成测试已移入 Execution 模块。下文的运行入口说明与验证记录保留其历史上下文。


本阶段只实现标记定义、角色名称选择和 Effect 标记操作列表。标记系统负责实体身上的标记管理，与属性效果运行时独立；后续处理层数、来源、有效期、叠加、刷新和移除，不执行伤害或属性修改。本文描述本阶段实际支持范围，不表示标记运行时已经实现。

## 数据归属

| 位置 | 当前内容 |
| --- | --- |
| `MarkerCatalogAsset` | 独立标记定义库，每项包含稳定 ID、名称、分组和说明。分组只影响展示，不自动赋予产生资格。 |
| `CharacterAttributeAsset.MarkerCatalog/ProducedMarkerIds` | 角色显式选择能够产生的标记，Inspector 按名称显示；不会在角色初始化时自动挂载。 |
| `EffectGraphAsset.MarkerCatalog/MarkerOperations` | 有序的增加或移除请求草稿，不绑定来源角色，不保存运行标记。 |

通用标记也需要在角色中显式勾选。标记 ID 在同一库中非零且唯一，名称不能为空；名称变更不修改引用 ID。角色与效果显式引用标记库，不依赖扫描全部资产、显示名或 Unity 实例 ID 查找身份。引用库的发布版本必须与引用资产一致，使用当前 Schema 3 与发布版本校验。

层数上限、有效期、堆叠范围和刷新算法留待独立标记系统阶段确定，本阶段没有可执行规则字段，也不把标记定义当成 Buff 数值效果。

## 编辑入口

通过 `Assets / Create / AshACT / 标记定义库` 创建库。在 Inspector 中逐项编辑 ID、名称、分组和说明，点击“校验标记定义”。

角色 Inspector 保留属性区，并增加“可产生标记”：选择标记库，再点击“添加可产生标记”，从名称下拉框选择。更换库时保留已有 ID；找不到的引用提示警告，不自动替换。版本放在高级折叠区，结构版本只读。

Effect 节点编辑器右侧增加“标记操作 · 配置草稿”。选择标记库和施加者预览角色后，增加操作的下拉框只显示该角色在同一库中声明的标记。移除操作可以选择库内全部标记，不要求角色能够产生它。预览角色不写入 Effect，更换角色不删除、替换已有请求。

每项请求保存：

- 执行时机：施加时、周期执行时；周期请求要求效果配置正整数周期。
- 操作：增加或移除。
- 接收对象：效果目标或效果来源。
- 标记：名称下拉选择，内部保存稳定 ID。
- 增加：正整数请求层数。
- 移除：全部来源或本次效果的来源，以及指定层数或全部。

请求可以上移调整顺序或删除，编辑通过 SerializedObject 支持 Undo 和保存。“校验标记草稿”只检查配置有效性与已选来源角色的产生资格，不执行请求、不创建标记状态。正常结束或离场等结束时机尚未提供。

`AshACT / 创建标记配置示例` 使用 AssetDatabase 创建独立的标记库、角色和效果三个示例资产，使用唯一文件名避免覆盖，自动带入来源预览角色。示例包含通用燃烧、专属苍炎和用于移除的霜寒；不会生成场景、Prefab 或 SessionSetup 资产。

## 配置校验与运行会话编译

`MarkerAuthoringValidation` 提供库、角色和效果草稿校验，拒绝无效或重复编号、缺失引用、无效操作、非法请求层数、缺少周期及版本冲突。角色声明也进入现有角色和会话编译校验。

“会话编译”是 `ConfigurationCompiler.TryCompileSession` 在初始化前校验 Catalog、角色、效果和实体输入，并生成锁定的只读运行配置；不是 C# 编译、打包或生成可执行文件。`AttributeRuntimeHost.TryInitialize` 只有编译成功才发布新会话，失败保留旧会话。资产修改不会直接改变已运行会话。

独立标记运行时尚未接入。因此，非空 `MarkerOperations` 可以编辑、校验与保存，但 `TryCompileEffect/TryCompileSession` 明确返回 `MarkerRuntimeUnavailable`，不静默忽略请求后生成可运行结果。角色清单暂时只是已校验的声明，不声称当前运行时已经执行产生权限校验。

## 外部标记管理器接口预留

`AshACT.Effects` 已提供纯 C# 契约 `IMarkerRequestHandler`、`IMarkerRequestTransaction`、`MarkerRequest` 和 `MarkerRequestResult`。该程序集保持 `noEngineReferences: true`，接口不依赖 ScriptableObject、GameObject 或 Editor，外部标签／标记管理器可以实现它。这里统一使用“标记”命名，与标记定义库对应。

`MarkerRequest` 是不可变值，保存增加或移除、稳定标记 ID、来源实体、实际接收实体、整数帧、请求层数和移除范围／方式。可附带 Effect 定义、实例及操作序号作关联上下文，也允许没有 Effect 的其他系统构造请求。实例非零时必须带有效定义 ID；该上下文不充当幂等键。接收对象已经解析为实体，不把来源／目标选择项或可变资产交给管理器。全部移除使用 `Count = 0`，其他方式必须为正整数；默认请求无效，构造非法组合会抛参数异常。

接口入口为：

```csharp
MarkerRequestResult TryPrepare(
    IReadOnlyList<MarkerRequest> requests,
    out IMarkerRequestTransaction transaction);
```

由外部管理器按配置决定上下限、叠加、刷新和移除，不在 Effect 中实现这些规则。管理器绑定一个模拟域及其锁定标记定义，所有调用在同一模拟线程同步执行。输入为非空的同帧有序批次；应逐项检查有效性，如需长期保留输入须复制集合。

为了支持未来属性和标记共同原子提交，接口有以下约定，但当前没有执行协调器或管理器实现：

1. `TryPrepare` 只改变管理器的候选状态，不改变可见状态，不发回调。失败必须丢弃整个候选批次并返回空事务。
2. 准备成功时必须返回非空事务。满层忽略等正常规则可以成功且无变化；成功只表示可提交，不代表已增加层数或已修改状态。
3. 协调方确认整笔操作可提交后调用一次 `Commit()`。实现方须保证提交不失败、不抛异常且不执行外部回调；这是对未来管理器实现的契约要求，并非接口自动提供的保证。
4. 未提交时 `Dispose()` 丢弃候选状态；提交后只释放资源，不回滚。所有系统都提交后，再由未来协调方安排通知。

`MarkerRequestError` 区分未连接管理器、无效请求、不支持的操作和准备失败。默认结果是 `HandlerUnavailable`，不能被误认为成功；附加说明只供诊断，不决定模拟行为。

本次只预留接口与请求数据。没有创建全局管理器、事件广播、自动查找、空实现或默认成功处理器，也没有把处理器挂到 Setup／Session、执行草稿到请求的转换、调用接口或解除会话编译限制。未来接入还需实现管理器及事务、配置转换、确定性调度、产生资格检查和状态保存恢复。现有编辑器的草稿状态提示继续有效。

## 旧标记方案已移除

当前只有标记定义、角色可产生声明、操作草稿和外部管理器接口。旧的 EffectGraphAsset.MarkerIds、EffectDefinition.Markers、EffectController.GetMarkerCount、MarkerConfiguration 和 SessionSetup.Markers 已全部移除，不再保留兼容入口、运行计数或界面折叠区，也不自动把旧标记翻译成新请求。

纯 C# 的 EffectDefinition.TryCreate 不再接收标记数组，完整会话编译的数组重载不再接收标记清单。调试窗口只组装属性库、角色实体和效果，状态面板不再从活跃效果显示标记。

这是配置结构的破坏性变更，SchemaVersion 升为 3，旧 Schema 1/2 必须先显式迁移，不能静默接受。效果状态规范字节协议升为 2，删除旧标记编码段，新旧规范字节和 Hash 不兼容；当前没有磁盘／网络反序列化，不提供旧快照迁移。

本项目已通过当前 Editor 的 AssetDatabase 迁移 16 个配置资产，保留原 GUID、编号、数值、节点连接、位置及新标记草稿，只更新结构版本并移除旧标记字段。迁移前文件和内存配置备份、逐项核对结果位于忽略的 `.codex/runs/remove-legacy-markers-20261019T1217/`。旧标记的随效果结束语义不会被推断成新系统的独立有效期。

未来标记请求执行成功后，标记状态与 Effect 生命周期独立；瞬时 Effect 可以请求产生持续标记，结束不自动撤回。当前没有执行管理器或接口分发，含非空 MarkerOperations 的运行配置仍返回 MarkerRuntimeUnavailable。
