# AshACT 属性修改器最终设计方案

状态：已确认的设计方案；尚未实现运行时 C#、可视化编辑器或 Unity 资源。本文中的类型名称和接口职责均为拟新增设计，不代表仓库已有 API。

实施进度：上面的状态与下文“当前主工作区”描述保留最初方案确认时的基线；现在属性基础与效果运行时已分别实施，实际 API、程序集和验证边界以[第一阶段](AttributePhaseOne.md)及[第二阶段](AttributePhaseTwo.md)为准。本文跨角色依赖、生命周期快照等内容仍是后续设计，不代表已交付能力。

## 1. 依据、范围与前置条件

- 本地 [GAS 中文参考](../../Assets/AshACT/Refs/GASDocumentation_Chinese-main/README.md) 的 4.3–4.5 节提供 Attribute、BaseValue/CurrentValue、GameplayEffect、Modifier 和效果实例等概念。参考目录只有 README 和图片，没有可复用的 Unreal C++ 实现。
- 当前主工作区的 Assets/AshACT 只有 Refs，没有属性系统、效果系统或 asmdef。本方案不假设已有 AbilitySystemComponent、GameplayTag 或事件总线。
- 定点数源码已从用户指定的 [Physics2D 分支 FixedPoint 实现](https://github.com/Ash-final-light/AshFramework/tree/Physics2D/Assets/AshFramework/Physics/FixedPoint) 复制到当前工作区的 [Assets/AshFramework/Physics/FixedPoint](../../Assets/AshFramework/Physics/FixedPoint/FP64.cs)，保留原有 .meta 文件和计算逻辑；为符合本项目规范，C# 单行控制流和代码块已按 Allman 风格展开。Framework.FixedPoint.FP64 使用 long Raw 的 Q32.32。该目录没有独立 asmdef；后续属性系统实现时仍需核实并确定程序集引用。
- 目标是 Windows 平台内的确定性帧同步，不承诺跨平台逐位一致。单机模式也使用同一套逐帧模拟逻辑。网络传输、预测与回滚调度器不属于属性修改器首期实现。
- 只定义通用机制，不内置 Health、Mana、Attack、MoveSpeed 等具体属性。后续由开发者通过配置创建属性。

文中 Attribute 指角色数值属性；Modifier 指修改属性的运算项；Effect 指应用到目标的一次规则或持续状态。标记是 Effect 的一种内容，不是 Attribute。

## 2. 不变量与数据所有权

1. 属性定义和效果定义是可共享的只读配置。每个角色独立选择属性集合、初始值及边界，并创建自己的 AttributeStore。不存在保存所有角色数值的全局单例。
2. 角色的属性集合在战斗开始时固定。战斗中允许 BaseValue、CurrentValue 和活跃效果变化，不允许动态增删属性。不同角色可以拥有不同属性集合。
3. EffectDefinitionId 标识“同一种效果”；每次施加分配独立 EffectInstanceId。重复施加互不刷新、合并或共享持续时间。效果名字、标签、数值和来源都不作为效果身份。
4. AttributeStore 只保存属性值和修改器索引；活跃效果及标记由效果实例管理。纯标记不要求目标存在任何 Attribute。
5. 模拟状态仅使用稳定实体 ID、定义 ID、实例 ID、整数帧号和 FP64 Raw。运行计算不得读取 Unity Time、GameObject.GetInstanceID、浮点随机数、资产加载顺序或网络到达顺序。
6. 所有模拟命令按约定顺序执行。命令提交后，其变化对本帧后续命令可见。属性变化通知不能在正在结算的事务中递归写入；由通知产生的新命令进入下一帧。

## 3. 可视化配置与导出

编辑器的最终形态是节点连接区、配置面板和时间轴。当前任务只设计属性修改器相关节点及运行协议，不提前实现完整技能编辑器。开发者可为每个角色选择不同的属性配置；共用定义资产不意味着角色共用运行值。

| 配置单元 | 职责 |
| --- | --- |
| AttributeDefinition | 稳定 AttributeId、显示信息、Resource/Stat 分类、可配置边界；Resource 可引用另一个 Stat 作为动态最大值。 |
| CharacterAttributeConfig | 某个角色拥有的 AttributeId、初始 BaseValue 和角色自己的范围配置。 |
| EffectDefinition | 稳定 EffectDefinitionId、持续类型、整数帧时长和周期、标记 ID、修改器节点列表。 |
| Modifier 节点 | 连到目标属性，声明 Add、Multiply、Divide 或 Override、优先级和数值输入。 |
| 数值节点 | 常量、SetByCaller、读取来源/目标的 BaseValue 或 CurrentValue，以及确定性的 FP64 算术组合。 |
| 时间轴 | 展示施加、周期触发和到期的整数帧语义。 |

节点图是配置，不执行任意 C# 回调；运行逻辑由通用 C# 引擎解释或执行导出数据。首版属性读取仅可选择本次效果的来源角色或目标角色，不能任意查找场上实体。持续修改器的来源和目标属性读取均为实时读取；周期效果每次触发也重新读取当时属性。需要固定常量时直接使用常量或 SetByCaller 输入，不在首版提供可切换的属性读取快照模式。来源离场时的冻结快照属于生命周期规则，见第 8 节。

编辑器输入和显示精度为 4 位小数；导出时直接把十进制文本作为精确分数转换为 FP64 Raw，采用就近舍入、正好居中时取偶数，不经 float/double 中转。运行时保留 Q32.32 精度，不在每步运算后截成 4 位。运行配置中的所有数值以 Raw 保存。配置必须显式版本化，战斗开始后锁定版本；编辑器修改在下一次战斗初始化时生效。导出时验证 ID 重复、参数缺失、范围、节点连接及可静态发现的依赖环。跨角色实例关系造成的环在应用时验证。

## 4. 拟新增运行时结构

| 类型或模块 | 责任 |
| --- | --- |
| AttributeId、EffectDefinitionId、MarkerId | 显式分配的稳定值类型；0 作为无效值，不从名称哈希或 Unity 实例 ID 推导。 |
| AttributeStore | 每角色一份；保存固定属性集合、BaseValue、CurrentValue、边界、修改器索引。 |
| AttributeAggregator | 对一个属性的持续修改器做确定性重算与截断；不管理效果时间。 |
| EffectDefinition、EffectSpec | 分别表示只读效果配置和本次施加的来源、SetByCaller 参数等输入。 |
| ActiveEffect | 一次独立施加；保存实例 ID、来源和目标 ID、开始/结束帧、下次周期帧、标记、修改器句柄、来源读取绑定。 |
| EffectController | 管理目标身上的活跃实例、到期、周期、移除和标记查询；同一 MarkerId 可由多个独立实例提供，查询时按实例计数。 |
| DependencyCoordinator | 在同一模拟域内维护跨角色属性依赖有向图，检查环、传播脏节点并按稳定拓扑顺序重算。 |
| SimulationCoordinator | 规定 60 Hz 帧阶段、命令顺序、跨 Store 事务、死亡/离场事件、快照与恢复。 |
| AttributeChange | 提交后的只读变化记录，包含实体/属性 ID、旧新 Base 和 Current、事务与原因。 |

依赖方向建议为 FixedPoint → Attributes → Effects → Simulation；Unity 适配层负责序列化配置和角色生命周期，Editor 层负责图形界面与导出。实际 asmdef 划分须以已复制源码的真实程序集边界验证；不能让纯计算层依赖 UnityEngine 或 Editor。

来源读取绑定在活跃实例中有 Live 与 Frozen 两种运行状态。Live 指向来源角色的稳定 EntityId；来源死亡或离场时切到 Frozen 并保存该次生命周期结束时的属性快照。该状态不是策划可切换的捕获模式。

## 5. FP64 数值和属性规则

FP64 采用 Q32.32，模拟时间使用整数帧。统一允许配置的数值边界为 [-1,000,000,000, +1,000,000,000]；每个属性还必须配置更窄或相同的边界。结果超过属性边界时截断；FP64 可表示范围溢出、除零或无效配置使整个相关事务失败，不允许先溢出回绕再截断。

现有 FP64 的加减直接操作 long Raw，乘除也不能直接当作完整的溢出检测入口。实现时需在属性系统的确定性运算门面使用宽中间值或等效检查，覆盖加、减、乘、除、聚合及配置转换。乘除结果沿用该 FP64 实现向负无穷取整的约定，不能让安全包装层改写数值语义。检查与舍入规则必须固定，并通过 Windows 上重复运行及重演验证。不能在模拟中先转 float/double 计算再转回 FP64。

BaseValue 是永久基础值，不代表最大值；CurrentValue 由最新 BaseValue 和活跃持续修改器重算。效果到期移除修改器后重新求值，不用“反向执行”撤销。Resource 的消耗和恢复、周期伤害或治疗修改 BaseValue；Resource 的最大值由独立的 Stat 属性提供，不预置任何具体资源名称。首版 Resource 不直接接收持续修改器，需要持续扩容时修改其最大值 Stat。

资源上限下降时保留绝对数值，超出新上限的 Resource BaseValue 被永久截断，再重新计算 CurrentValue。上限日后恢复不自动补足；上限升高也不按比例增加资源。一般 Stat 的 CurrentValue 截断不反写 BaseValue。

持续修改器按稳定的应用序号遍历并计算：

    A = Σ(Add 数值)
    M = max(0, 1 + Σ(Multiply 数值 - 1))
    D = 1 + Σ(Divide 数值 - 1)
    普通结果 = ((BaseValue + A) × M) ÷ D
    CurrentValue = Clamp(Override 胜者数值，或普通结果)

Multiply 输入为非负的完整倍率；两份 1.5 的持续倍率得到 2，而不是 2.25。Divide 输入至少为 1，因此聚合分母不小于 1；两份 ÷2 作用于 Base 120 时，分母为 3，Current 为 40。Override 优先于其他运算，最高优先级获胜，同优先级取最后应用的实例；移除胜者后重算剩余项。所有中间运算也必须通过溢出检查。

瞬时效果依配置顺序对事务中的 BaseValue 逐项执行 Add、Multiply、Divide、Override。周期效果每次到点也执行一次瞬时 Base 修改；已执行的历史结果不会因来源属性后来变化而追溯修改。因此 Base 100 连续接受两次瞬时 ×1.5 后为 225，而两份持续 ×1.5 得到 Current 200。

## 6. 效果应用、实时依赖与原子事务

一次对单个目标的效果应用顺序如下：

1. 创建该目标专属的应用上下文，分配候选实例 ID；纯瞬时效果成功执行后不留下活跃实例。
2. 验证该目标需要的全部属性是否存在、SetByCaller 必填项是否齐全、数值和除数是否合法。若任何必需属性缺失，包含标记的整个效果在该目标失败；别的目标独立处理。若希望标记总能成功，应配置为独立效果。
3. 将来源/目标读取节点和目标属性加入候选依赖图。节点声明读取 BaseValue 或 CurrentValue；读取自身 CurrentValue 并修改自身 CurrentValue、跨角色互相依赖等环均拒绝整个应用。
4. 在工作状态中执行瞬时 Base 命令或注册持续修改器、标记及周期计时。持续修改器实时求值；相关来源或目标属性改变时沿依赖图重算。
5. 对命令影响的所有 Store 和跨角色依赖闭包按确定拓扑顺序重算、执行属性和资源边界规则。全部成功才一起提交实例、数值、依赖边和计时器。溢出、除零、依赖环等错误均不留下部分修改。
6. 提交后暂存只读 AttributeChange 和效果事件，在本帧发布阶段按稳定顺序发出。通知回调提出的新写入排入下一帧命令队列。

一个多目标技能按 EntityId 依次应用；每个目标作为独立应用单元，某目标失败不撤销其他已成功目标。单目标命令引起的跨角色实时依赖变化则属于同一事务闭包，不能仅提交目标 Store 后再让其他角色重算失败。同步错误返回结构化原因，不依赖异常决定游戏状态。到期、周期调度或死亡清理等必执行系统步骤若无法成功重算，则停止并报告该帧确定性错误，不能悄悄跳过该步骤后继续模拟。

依赖图节点至少包含 EntityId、AttributeId 和 Base/Current 读取类型。相同帧多个属性变化后按确定的节点排序拓扑重算；变化检测比较 FP64 Raw，不以界面 4 位显示精度吞掉变化。活跃效果不采用自动堆叠规则；多个独立实例可以共同向同一属性贡献修改器。

## 7. 60 Hz 帧流程

逻辑帧编号为整数；每帧执行一次物理 Step，步长与选用的物理分支保持一致。帧内阶段固定为：

| 阶段 | 行为 |
| --- | --- |
| 1. 到期 | 先移除本帧到期的效果、修改器、标记和依赖，重算受影响属性。 |
| 2. 输入/技能 | 命令按 (ControllerId, CommandSequence) 排序；多目标按 EntityId 排序。逐条事务提交，较早命令可影响较晚命令的判定。 |
| 3. 周期与属性 | 活跃实例按稳定实例 ID 处理本帧到期的周期执行，逐次按事务结算；完成本阶段所需的属性重算。 |
| 4. 物理 | 执行一次固定步长的物理 Step。 |
| 5. 碰撞与伤害 | 稳定排序碰撞结果并处理命中、伤害、效果及死亡。此阶段产生的移动属性修改影响下一帧物理 Step。 |
| 6. 发布/记录 | 发布已提交的只读事件，记录确定性状态或校验值；事件引发的新命令进入下一帧。 |

效果在施加当帧生效。持续区间为 [开始帧, 结束帧)，到期帧先移除，不在结束帧额外触发周期。首次周期执行在开始帧 + 周期间隔；周期和时长都用正整数帧数，持续效果可选择有限时长或无限时长。举例：开始帧 10、时长 3、周期 1，只在 11、12 帧触发。纯标记同样有独立的实例和到期帧。

实现时各阶段内部的事件序号、碰撞排序键和重复命令校验须写成协议并纳入测试。运行时不依赖 Dictionary 或 HashSet 的遍历顺序决定结算结果。

## 8. 死亡、离场和复活

死亡是外部战斗逻辑发出的确定性生命周期命令；属性系统不硬编码 Health 等属性判断死亡。来源角色死亡或以其他方式离场时：

1. 完成导致该次死亡/离场的命令及其属性依赖重算。
2. 在该角色自己的活跃效果清理前，保存此刻所有属性的 BaseValue、CurrentValue 的 FP64 Raw 快照。多个旧效果可引用同一份不可变快照。
3. 将其他目标身上仍存活、以该角色为来源的效果从 Live 绑定切换为 Frozen，解除跨角色实时依赖；它们的剩余时长和标记继续运行。
4. 清除死亡目标自己身上的全部活跃效果、持续修改器和标记，再完成依赖重算与事件发布。

如果 A 死亡，A 施加在仍存活的 B 身上的旧效果继续读 A 的死亡快照；A 身上的旧效果全部结束。A 复活后，B 身上这些旧效果仍读旧快照；复活后新施加的效果才实时读 A。A 再次死亡时，新效果冻结于新的死亡快照，旧效果仍保持自己的旧快照。直接离场使用相同规则。

如果目标 B 死亡，B 身上的所有效果和标记结束。B 复活后没有旧效果，复活时具体资源值由战斗逻辑初始化，不由属性修改器自动恢复。若来源和目标同时死亡，生命周期命令按确定的实体/事件顺序处理，但每个来源的快照都在清理自己身上效果之前取得。

## 9. 保存、调试与验收

为帧同步重演预留完整确定性状态的保存/恢复：各角色属性集合版本与 Base/Current Raw、活跃效果实例、来源绑定的 Live/Frozen 状态及冻结快照、修改器句柄和应用序号、到期帧/下次周期帧、稳定实例 ID 计数器、待处理命令和确定性随机状态。恢复后重建依赖图，并校验同帧状态哈希。首期不要求实现网络预测或回滚调度器，但不能设计成无法保存这些状态。

调试面板未来至少显示每角色 Base/Current、Raw、边界、A/M/D 汇总、Override 胜者、活跃实例、来源绑定、周期和到期帧、依赖路径及失败原因。编辑器操作仅修改配置；运行调试数据不回写共享定义。

后续实现的关键验收用例包括：

| 场景 | 预期 |
| --- | --- |
| Base 100，两份持续 ×1.5；两次瞬时 ×1.5 | 前者 Current 200；后者 Base 225。 |
| Base 120，两份持续 ÷2 | Current 40。 |
| 高优先级 Override 与同优先级后施加 Override | 高优先级胜；同优先级后者胜，移除后重算。 |
| A 属性实时驱动 B 的持续修改器 | A 值改变时，B 在同一命令提交中确定性重算；形成环时整个新效果失败。 |
| A 死亡、复活、再次死亡 | B 的旧效果始终读第一次快照；新效果先实时读 A，第二次死亡后读第二次快照。 |
| B 死亡、复活 | B 的修改器与纯标记被清除，复活后没有旧效果。 |
| 目标缺少属性且效果同时包含标记 | 该目标整个效果失败；其他目标独立成功。 |
| 资源上限降低再升高 | 超出新上限的 Base 永久截断，不自动恢复。 |
| 周期结束边界 | 到期帧无额外触发；已经修改的 Base 不因效果结束回退。 |
| 任一中间 FP64 溢出或除零 | 相关跨角色事务原子失败，数值、实例、依赖和计时器均不改变。 |
| 同一输入与初始快照重复运行 | Windows 上得到相同的 FP64 Raw、实例 ID 和状态哈希。 |

## 10. 实施顺序与当前交付

1. 基于已复制的 FixedPoint 源码核实程序集边界；定义经过溢出检查的 FP64 运算入口和确定性配置转换。
2. 实现稳定 ID、每角色 AttributeStore、四种操作、资源规则、原子事务及纯 C# 数值测试。
3. 实现 EffectDefinition/ActiveEffect、纯标记、独立实例、周期和稳定帧调度。
4. 实现跨角色依赖图、实时重算、生命周期冻结快照、完整保存/恢复及确定性重演测试。
5. 最后接入 Unity 配置资产、节点编辑器、导出校验和运行调试面板；Editor 测试针对本项目的真实目标运行。
