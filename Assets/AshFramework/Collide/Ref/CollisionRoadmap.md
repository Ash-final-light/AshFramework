# AshFramework 碰撞框架完整路线图

## 目标和现状

为 **2D XY** 和**平面 3D XZ** 游戏提供碰撞框架。每个世界可配置空间索引，可由 Unity `FixedUpdate` 或外部固定逻辑帧驱动，支持角色防穿墙、滑墙、触发事件和路径伤害查询。刚体动力学、冲量、摩擦和关节留作独立扩展。

`Collide` 分支的开发基线为 `f0082e8`，已有均匀网格、基础形状和复合体接触，以及即时与跨帧位置修正。最近本机验收为 **268 项 EditMode 测试、4 个场景 6 组 Play 检查通过**。现有均匀网格继续作为功能开发和索引对照的基线。[位置修正实施计划](PositionCorrectionPlan.md) · [示例与操作说明](../Samples/README.md)

## 实施顺序

| 阶段 | 开发内容 | 验收标准 |
| --- | --- | --- |
| **1. 传送** | 增加独立的 `TryTeleportTo`，提交落点并同步索引。落点可报告重叠，由调用方决定是否修正。传送成功后结束原位置上的渐进修正。 | 落点接触可见，旧空间位置查不到角色。非法落点或同步失败时恢复原位置。传送跳变不产生连续路径。 |
| **2. 范围查询与圆形角色扫掠** | 在世界层增加圆和矩形范围查询。用 `IBroadPhase2D` 找候选，再用现有精筛返回按 `Body ID` 去重、排序的结果。扫掠首版支持单圆角色平移，对圆、AABB、OBB 及其复合墙找最早接触。 | 半径 `1` 的角色从 `x = 0` 向 `x = 5` 移动，遇到左表面在 `x = 2` 的墙时，圆心停在 `x = 1` 的接触边界允许误差内。覆盖薄墙、旋转墙、跨网格、相切及多个同时命中。 |
| **3. 滑墙与实际路径** | 命中后去掉剩余位移中朝墙的分量，沿墙再扫掠。墙角同时考虑同一时刻命中的阻挡面。首版默认最多处理 4 次阻挡，保留最后的安全位置。记录实际通过的分段路径和段的逻辑帧内时间。 | 斜撞可沿墙移动，墙角和窄缝能结束。覆盖从墙边向外走、沿墙走和零位移。初始穿透交给现有 `Snap` 或 `Gradual`，推开位移单独记录。 |
| **4. 自动驱动与触发事件** | 每个世界选一种驱动。旧场景默认仍可手动 `Step`，普通场景可挂 `FixedUpdate` 驱动，战斗逻辑可显式调用拟议的 `TryTick(frameId, deltaTime, …)`。两种驱动共用帧流程，配置阶段拦截同一世界的重复驱动。触发区按成功帧末的 Body 对产生 `Enter / Stay / Exit`。 | 相同固定步长和输入在两种入口下得到相同结果。生成、禁用、销毁、换世界后结果及时更新。一次 Tick 内多次内部检测只发布一次事件，失败帧不发事件，节点停用后不会继续推进旧修正。 |
| **5. 伤害查询与结算** | 支持圆和矩形区域的当前位置及路径查询。攻击范围和目标都可在同帧平移，用时间重叠的路径段计算相对运动。几何层返回去重的目标 `Body ID`，玩法层负责一次、持续、定期检测和 `OnHit`。 | 冲刺穿过固定伤害区、移动攻击经过移动目标均可命中。两条路径在空间相交但经过时间不重合时不命中。同一目标的多个子形状只产生一个命中 ID。传送只检查符合规则的端点，推开位移不计作经过。 |
| **6. 空间索引与性能** | 保留均匀网格，依次实现空间哈希和松散四叉树。世界初始化时按配置选择索引，各实现共用 `IBroadPhase2D`。在代表性关卡记录同步成本、候选数、查询耗时和分配，再按数据决定几何脏更新、静态代理或局部同步的优先级。 | 三种索引面对相同数据时，精筛后的 Body ID、碰撞对和扫掠命中一致。覆盖负坐标、边界相切、大物体、跨区移动和大量启停。记录稀疏、聚簇和高移动比例场景的实测数据。 |

索引的共同查询语义和边界见[空间划分设计参考](SpatialPartitioningSurvey.md#8-面向-ashframework-的双方案设计与验证建议)。

## 自动驱动的单帧流程

```text
读取本帧移动、传送和配置变更
    → 同步起始几何和空间索引
    → 按稳定 Body ID 顺序处理移动、扫掠、滑墙和位置修正
    → 同步最终位置，生成最终碰撞对和所需接触
    → 用最终碰撞对比较触发状态，用实际路径计算伤害命中
    → 发布本帧结果，再调用事件和 OnHit
```

- 每个逻辑帧只发布一次结果，同一帧号的重复提交不推进。回调产生的移动、禁用等命令进入下一帧。查询或索引失败时报告失败，保留上次成功的触发状态。单个 Body 配置无效时，沿用现有暂停和诊断机制。
- `BlockingMask` 决定角色移动时哪些层产生阻挡，触发和伤害各用自己的查询条件。触发事件表示帧末占用变化，一帧内穿进又离开的玩法使用路径查询。逻辑高度保留当前的默认检测行为，业务查询可显式按高度过滤。
- 首版连续计算按平移处理，连续段内朝向和尺寸固定。单圆角色防穿墙面向固定障碍，旋转扫掠、复合移动体、移动平台和游戏中索引热切换在核心流程验收后单列。

## 验收方式

每个阶段先跑针对性测试，再复跑完整碰撞程序集。接入新的 Unity 行为后，在本机 Play 模式用对应场景记录实际位置、接触、事件和停止原因。第一批只交付传送与落点同步，第二批先让圆形角色稳定停在墙前，再加滑墙。
