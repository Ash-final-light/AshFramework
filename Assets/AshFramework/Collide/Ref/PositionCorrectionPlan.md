# 位置修正实施计划

## 已验收基线

1. 碰撞世界通过 `IBroadPhase2D` 注入索引。`Step` 同步 Body 几何和 AABB，按需输出规范化的 Body 对及子形状接触。
2. 圆、AABB、OBB 的六种组合已能计算法线和穿透深度。相切仍是接触，深度为零。
3. Unity 侧的形状、Body 层配置、角色移动配置和位置修正管理器各有独立组件。角色的 `BlockingMask` 决定哪些层参与修正。墙用 `WorldSolid`，触发区用 `Trigger`，触发区的重叠仍由碰撞世界输出。
4. `Immediate + Snap` 已支持单角色对固定障碍的多次修正。每次选择最新接触中最深的一条，写回角色 `Transform` 后重新 `Step`。默认最多修正 4 次，容差约 `0.00001` 世界单位。返回最后一次有效检测的数据和停止原因。
5. 最近一次完整验收实跑 **251/251** 项 EditMode。墙角示例从 `(1.5, 1.5)` 经两次修正到 `(1, 1)`，剩余穿透为零。夹缝宽 `1.5`、角色直径 `2` 时，在第 4 次达到上限，报告剩余穿透 `0.5`。

现状见 [碰撞模块 README](../README.md) 和 [示例说明](../Samples/README.md)。

## 同步修正开关

沿用每个碰撞世界一个 `PositionCorrectionManager` 的结构。角色移动组件提供位置写回入口及本次策略，管理器由上层逻辑帧显式驱动，碰撞世界继续提供同步和接触结果。角色的 `Transform` 是本阶段的位置来源。

- `CharacterMovement.CanCorrectPosition` 初始值取自 `Timing`，`Immediate` 为开启，`Deferred` 为关闭。管理器接管后通过 `TrySetCorrectionAllowed` 切换。
- 关闭时仍通过 `TryMoveAndCorrect` 移动并执行 Step，返回 `Skipped`、碰撞对、接触和最大阻挡深度。开启时沿用 `Snap` 的同步迭代，`BlockingMask` 决定哪些层参与修正。
- 从关闭切到开启时，管理器在同一次调用中从角色当前位置重新检测并求解。角色已离墙、仅接触触发区或深度在容差内时直接完成。关闭或重复设置时保留调用方原有碰撞结果。
- Step 失败时恢复调用前的位置并清空输出。若本次操作是开启，开关保留为关闭，以便重试。

验收覆盖半径 `1` 的圆与墙面 `x = 2`。开关关闭时圆心在 `x = 1.5`，穿透 `0.5`。开启返回前圆心移到 `x = 1` 并与墙相切。另覆盖已离墙、触发区、重复开启、墙角、失败回滚，以及 XY/XZ 平面映射。

## 跨帧渐进修正

- 渐进模式沿用同一个开关。开启后从当帧开始按 `CorrectionSpeed × 固定逻辑帧时长` 分配修正距离，后续逻辑帧继续处理。同一角色同一帧只分配一次预算，帧内各段共享预算。关闭期间不累计预算。
- 从最新 `Step` 结果取最深的有效阻挡接触。沿角色一侧的分离方向移动，单段距离取当前穿透深度与剩余预算的较小值。每次实际移动后重新同步并获取接触。
- 通过带逻辑帧的 `TryMoveAndCorrect` 或 `TrySetCorrectionAllowed` 开始。达到容差时完成。预算用尽或达到本帧迭代上限时，若仍有穿透，返回 `InProgress`，由下一逻辑帧调用 `TryContinueGradualCorrection` 继续。位置经量化后无法变化时报告 `NoProgress`。默认累计上限为 60 个处理帧，达到后报告 `FrameLimit` 和剩余穿透。
- Step 失败时回滚本帧并清空本帧输出，保留之前各帧完成的位移。角色停用、销毁、解绑或换世界后结束跨帧处理。

## 渐进修正验收

| 场景 | 通过标准 |
| --- | --- |
| 渐进限距 | 例如深度 `0.5`，每帧预算 `0.25`，第一帧修正 `0.25`，第二帧达到相切。墙角两次不同方向的修正共用同一帧预算。 |
| 关闭后再开启 | 关闭时没有修正，开启后按单帧预算推进，关闭时长不放大首帧位移。 |
| 窄缝、量化停滞与失败 | 窄缝在累计上限内结束并返回剩余穿透。位移无法表示时报告 `NoProgress`。Step 失败时核对回滚及输出清空。 |
| 现有回归 | 单墙同向双接触只推一次，墙角两次修正，触发区仍有接触，XY/XZ 保持各自平面映射。 |

实施时先跑相关定向用例，再用项目工作流检查 C# 布局、格式、构建及整个碰撞程序集。Editor 验证绑定 AshFramework 的唯一 ready 实例。示例中手动核对开启修正和逐帧限距，记录角色位置、帧数与停止原因。

## 后续接入顺序

1. **指定坐标传送**。保留独立的 `TeleportTo` 入口，传送后同步碰撞数据。传送目标与由接触算出的 `Snap` 修正位置分别记录。
2. **扫掠与滑墙**。按计划位移找最早接触，在墙前停下或沿墙继续移动，输出角色实际经过的路径。已有重叠可交给位置修正。通用 `IsStatic`、每 Body 几何脏标记和局部索引同步，在出现移动平台、可推物体或全量刷新成本明确后再安排。
3. **伤害查询**。查询圆或矩形范围及实际路径，按攻击与目标的有效时间检查中途经过，返回去重 Body ID。一次检测、持续检测、定期结算与 `OnHit` 由玩法层管理。拟默认排除初始重叠产生的推开位移和传送跳变。
