## 1. 实施方向

采用“定点二维几何核心 + 松散四叉树/空间哈希可选粗筛 + 共用精筛 + 共用事件层”。平面 3D ARPG 使用逻辑 XZ 平面，2D 游戏使用逻辑 XY 平面，精筛算法始终处理同一套二维几何数据。根据用户后续确定的方向，3D 高度采用 1/2/3 三档逻辑高度，使用高度集合匹配及公共碰撞规则过滤，具体设计见第 7.1 节。

参考项目值得保留的是：简单形状专用检测、形状配对分派、复合碰撞体、候选进入精筛及前后帧配对生成事件的组织思路。公式和数据流需按当前项目的数值、变换和程序集契约重写。

首版建议明确支持 Circle、AABB、OBB 的全部 6 种无序配对及由这些形状构成的复合体。先完成布尔重叠与 Enter/Stay/Exit；射线精确查询作为后续独立阶段。Polygon、Segment、Capsule、接触流形和连续碰撞检测按实际需求扩展，不以占位接口宣称支持。

## 3. 移植时必须解决的问题

### 3.1 复合包围盒必须覆盖全部子形状

[ColliderPrefab.GetBounds](D:/UnityProject/LockstepCollision/Assets/Collision2D/ColliderPrefab.cs:12) 只通过 `parts[0]` 获取一个子形状的范围；[ColliderProxy.GetBounds](D:/UnityProject/LockstepCollision/Assets/Collision2D/ColliderProxy.cs:73) 只给缓存范围叠加整体平移。

实施时按世界姿态更新每个子形状，计算子形状世界 AABB，再求全部子 AABB 的并集作为代理范围。平移、旋转、子形状修改、尺寸变化均使缓存失效。精筛即使正确，粗筛包围盒遗漏第二个子形状，也无法得到正确整体结果。

### 3.2 父子变换需要正确合成

[CTransform2D.operator +](D:/UnityProject/LockstepCollision/Assets/Collision2D/CTransform2D.cs:26) 直接相加位置和角度，没有把子形状偏移随父级旋转。[CollisionHelper.CheckCircle_OBB](D:/UnityProject/LockstepCollision/Assets/Collision2D/CollisionHelper.cs:28) 及 OBB 相关检测使用 `COBB.up`，没有使用传入世界变换的 `deg`。

刚体变换应按以下数学关系处理：

```text
childWorldCenter = parentPosition + Rotate(childLocalCenter, parentRotation)
childWorldRotation = parentRotation + childLocalRotation
```

当前项目 `FixTransform2D.TransformPoint` 可以处理局部点变换，角度使用弧度。首版运行时碰撞姿态建议限定为平移与旋转，缩放在定义/导入阶段按支持规则烘焙，避免引入剪切和椭圆后仍沿用圆/OBB 公式。

如果输入使用 `FixTransform2D`，应验证 Scale 为 One，不能把 default 值当 Identity：其默认缩放为零。圆的非均匀缩放、带剪切的矩形、零/负缩放应在首版导入验证中明确拒绝；正缩放也只有通过对应形状的烘焙规则才能接入。将来开放一般仿射变换时，利用已存在的 `Compose` 矩阵并升级形状表达，不能直接把合成矩阵解释为 OBB。

3D 适配器将世界 XZ 映射到逻辑二维坐标时，应从世界朝向的平面投影推导二维方向/角度，或提供显式逻辑角度。不能默认把 Unity Y 欧拉角原样当作二维逆时针角度；需用四个方向和 90° 转向用例确认坐标符号。带俯仰/翻滚的真实三维形状不在首版平面几何表达范围内。

### 3.3 半尺寸和边界规则必须统一

参考 `CAABB.size` 在公式里作为半尺寸；但 [CreateColliderPrefab](D:/UnityProject/LockstepCollision/Assets/Collision2D/CollisionSystem.cs:93) 将 BoxCollider 的完整 size 直接传入 COBB，且没有完整处理中心偏移、缩放和旋转。新的形状字段应明确命名为 HalfExtents，导入时执行对应转换。

参考圆–圆使用 `<=`，圆–AABB/OBB 使用 `<`，导致相切判定不一致。首版建议采用闭集规则：相切/接触算重叠，零间隙时返回 true；游戏若需严格穿透，再通过明确策略扩展，不在不同算法中混用比较符。

圆半径、矩形半尺寸要求正值；零尺寸碰撞形状首版拒绝，点和线段将来作为独立查询类型定义。宽相的边界测试仍可以包含零面积查询范围，两者应分别验证。

### 3.4 类型分派、配对身份与世界隔离

参考分派越界判断使用 `id > array.Length`，应采用完整范围和注册有效性检查；未知类型、未实现配对不能默默返回“没有碰撞”。开发期通过明确异常或能力验证暴露不支持的数据。

参考 `OnQuadTreeCollision` 按收到的 A/B 顺序拼接 pairId，没有在该入口规范化无序配对。本项目将对象对统一为 `(minId, maxId)`，并定义 ID 复用策略，例如带代次句柄，避免 A/B 反序重复和删除后身份混淆。

参考树包含静态回调与静态对象–节点字典。本项目改为每个碰撞世界独立状态，使多个关卡/世界、不同粗筛后端及测试实例可以并存；树节点信息不能泄漏到精筛和业务对象身份。

## 4. 复用当前数学库的方式

已核实当前数学核心程序集 [AshFramework.Math.asmdef](D:/UnityProject/AshFramework/Assets/AshFramework/Math/Runtime/AshFramework.Math.asmdef:1) 不依赖 UnityEngine、未开启 unsafe；Unity 转换单独位于 `AshFramework.Math.Unity`。

| 已有能力 | 实际公开入口 | 精筛中的用途 |
| --- | --- | --- |
| 定点标量 | `Fix64`，Q32.32，RawValue / FromRaw | 统一几何数据及原始值存储 |
| 方向与投影 | `FixVector2.Dot`、`Cross`、`Rotate`、`Perpendicular` | OBB 轴、投影和几何判断 |
| 安全距离比较 | `FixVector2.WithinDistance` | 圆–圆等只需比较距离的场景 |
| 角度 | `FixMath.SinCos`、`DegreesToRadians` | 弧度姿态及显式角度转换 |
| 变换 | `FixTransform2D.TransformPoint`、`ToMatrix`、`Compose` | 正确处理局部点与父子关系 |
| 通用几何 | `FixGeometry.ClosestPointOnSegment`、`Orientation` | 后续线段/凸多边形支持的基础 |

参考库 `LFloat` 使用 Precision=1000 的整数格式，和 Q32.32 的原始值不兼容。数据若有转换需求，应单独定义版本和显式量化流程，不能改类型名后直接复制原始数值或旧 epsilon。

需要特别处理程序集边界：`Fix64.FromWideRaw`、`FixVector2.SquaredRaw` 等内部成员不是碰撞程序集可调用 API。实现只依赖公开能力；必要的宽整数几何谓词放在碰撞核心自己的内部工具中，读取公开 RawValue，不为移植随意扩大 Math 的可见性。

数值实施原则：

1. 仅比较距离时优先直接比较宽整数平方，避免 `SqrMagnitude` 的最终 Fix64 平方值溢出；半径求和、坐标范围及中间量仍需检查。
2. AABB 比较、SAT 点积及投影和可使用 `System.Numerics.BigInteger` 保护中间值；不要假定“定点类型”自动防止全部溢出。
3. 旋转量化后的轴并非数学上无限精度的单位向量。圆–OBB 的局部距离比较、SAT 投影和包围盒计算需共用一致几何约定，并用临界用例验证误差。
4. 世界 AABB 必须保守包含精筛实际使用的世界形状；圆半径和 OBB 包围范围的舍入应向外保守处理。不能凭直觉加一个 raw epsilon 就宣称覆盖全部变换误差，应推导相应计算路径的误差预算或采用有证明的范围计算。
5. 建议首版容差默认为零；若引入接触容差，明确它是世界距离还是投影单位，并同步扩大宽相范围。不能仅让精筛接受范围外对象、却让粗筛提前排除。
6. 核心不读 Unity Transform/Time/Random，不通过 float 往返形成权威状态；定点计算以相同输入和明确次序为前提。当前 BigInteger 路线不承诺零 GC 或 Burst 兼容。

## 5. 首版形状与精筛算法

### 5.1 数据组织

形状定义保存局部几何；实例保存世界姿态、稳定句柄和过滤数据；复合体保存子形状与局部刚体姿态。每个模拟步先更新世界形状缓存、子 AABB 及整体 AABB，再更新空间索引。

不沿用 `COBB : CAABB : CCircle` 的几何继承链。拟使用明确形状标签和各自参数，公共范围由计算得到；共享的外接圆可以作为缓存优化，不能让矩形在类型语义上成为圆。具体类型名与存储布局在实施时确定。

**AABB 的旋转语义：** 世界轴对齐 AABB 才走 AABB 专用路径。局部矩形随父级旋转后，准备阶段转换为等价的世界 OBB，再进入 OBB 分派；不能仅把外接 AABB 当作原矩形的精筛形状。退化/量化角度的快速路径应依据验证后的几何约定选择。

### 5.2 六种配对

| 配对 | 拟实施算法 | 关键验收 |
| --- | --- | --- |
| Circle–Circle | 中心距平方与半径和平方比较 | 外切、内含、同心、大坐标 |
| Circle–AABB | 圆心到矩形最近点，再比较平方距离 | 边接触、角接触、圆心在内部 |
| Circle–OBB | 将相对位置投影/变换到矩形局部，再做圆–矩形检测 | 旋转、局部偏移、轴精度与相切 |
| AABB–AABB | 两轴闭区间重叠 | 边/角接触、包含、窄间隙 |
| AABB–OBB | SAT：世界两轴与 OBB 两轴 | 仅在斜轴上分离的反例 |
| OBB–OBB | SAT：双方各两条轴 | 近似平行、交叉、包含、旋转偏移 |

配对分派规范化形状类型与对应姿态一起交换，避免只交换形状而漏换变换。六种无序配对全部显式注册；未来扩展类型时，注册覆盖测试同步增加。

精筛结果首版以布尔重叠为准，不伪填法线或穿透深度。若以后需要角色推开、滑动或物理响应，另行增加接触生成及解算设计；布尔 SAT 的实现完成不代表这一层已完成。

### 5.3 复合体

先检查整体 AABB，再枚举子形状对；对每对子形状先测子 AABB，再调用真实形状精筛。只需要整体重叠时首个命中即可结束，复杂度上限与双方子形状数量乘积有关。多个子形状命中同一对象对，公共事件层仍只结算一次整体配对。

保留稳定子形状标识，为将来区分 Hurtbox/Hitbox、受击部位或收集全部命中预留数据位置；首版不默认收集全部子配对。空复合体、空形状和非法参数在注册前拒绝，避免 `parts[0]` 一类隐式假设。

## 6. 与两种粗筛及事件层的衔接

```text
逻辑状态：姿态、局部形状、碰撞规则、可选高度
                         ↓
准备世界形状 → 子 AABB → 整体二维 AABB
                         ↓
        松散四叉树 或 空间哈希
                         ↓
规范化候选对 → 去重 → 公共规则/高度/真实 AABB 过滤
                         ↓
             共用复合体与形状精筛
                         ↓
          本帧真实重叠集合 Current
                         ↓
        与 Previous 做集合差 → 排序后派发事件
```

首版先完整生成本帧候选，更新索引可做增量，但不要因此只精筛“本帧移动过”的对象。得到稳定结果后再评估移动列表与持久候选缓存优化。参考项目已经对旧配对重新精筛，借鉴这项持续相交意识，但若移植增量流程，还需重新应用当前碰撞规则和高度过滤。

事件语义为：`Enter = Current − Previous`，`Stay = Current ∩ Previous`，`Exit = Previous − Current`。每对只生成一次世界级结果，再按明确订阅规则通知双方；事件按规范化句柄排序。

删除或禁用对象时清理相关索引记录与配对，并按约定向仍有效订阅方发送一次 Exit；在派发期间请求增删的操作进入队列，在下一约定同步点生效，避免遍历集合时修改状态。句柄代次区分已删除对象与复用槽位。

高度变化、碰撞掩码变化和局部形状变化即使没有平面位移，也必须进入状态更新。碰撞检测关系与“谁收到事件”分别定义；首版建议使用对称的碰撞许可关系，攻击者单向命中规则放在显式业务过滤/查询中。

初始化或加载关卡时，运行时配置选择一个粗筛实现。若支持中途替换，由同一权威快照重建新索引，保留 Previous 配对和稳定对象身份；相同状态下，替换后精筛结果及事件序列应一致。

## 7. 平面 3D 与查询扩展边界

### 7.1 平面 3D 的三档逻辑高度

**方向：** 按用户提出的 1/2/3 设计三档逻辑高度，建议命名为“1 地面、2 低空、3 高空”。这些名称表示可配置的玩法状态，无须填写米制高度或随模型 Y 连续变化；标签的具体含义可由游戏调整。

#### 配置方式与内部表示

角色的受击形状通常选择一个当前高度档；攻击形状选择一个或多个能够覆盖的高度档。内部两者都转换成高度集合的位掩码，使用同一集合交集规则处理。

| 配置标签 | 内部掩码（二进制） | 含义 |
| --- | --- | --- |
| 1 地面 | `001` | 覆盖第 1 档 |
| 2 低空 | `010` | 覆盖第 2 档 |
| 3 高空 | `100` | 覆盖第 3 档 |
| 地面 + 低空 | `011` | 覆盖第 1、2 档 |
| 全高度 | `111` | 覆盖三档 |

标签编号 3 转成内部值是 `100`，不能直接把普通枚举值 3 当位掩码，否则会误表示 `001 + 010`。可提供单选角色高度、攻击高度多选和常用预设；界面隐藏内部二进制值。首版有效高度集合为 1～7 的掩码组合，零集合及未知位在有效形状注册时拒绝；禁用碰撞使用独立 Enabled 状态。

#### 判定规则

```text
高度匹配 = (形状 A 的高度集合 & 形状 B 的高度集合) != 0
最终重叠 = 碰撞类别/区域允许交互 && 高度匹配 && 二维精筛命中
```

攻击形状的集合表示“可命中的高度”，受击形状的集合表示“当前占用的高度”，二者相交才继续形状精筛。攻击/受击/阻挡等用途由已有碰撞类别契约区分，高度集合只回答高度兼容性。普通实体–实体阻挡同样用占用集合相交，但角色空中是否仍受地面阻挡应按玩法配置独立阻挡形状，避免一份受击高度无意改变全部移动规则。

例如：

| 攻击覆盖 | 目标当前高度 | 高度过滤结果 |
| --- | --- | --- |
| 扫地攻击：1 | 地面：1 | 允许，继续二维精筛 |
| 扫地攻击：1 | 低空：2 | 排除 |
| 普通挥砍：1、2 | 低空：2 | 允许，继续二维精筛 |
| 普通挥砍：1、2 | 高空：3 | 排除 |
| 对空攻击：2、3 | 地面：1 | 排除 |
| 全高度攻击：1、2、3 | 任意有效档 | 允许，继续二维精筛 |

集合允许不连续组合，例如只命中 1、3；不采用“攻击编号大于角色编号就命中”这样的隐式大小关系。玩法希望高空攻击兼容低档时，在预设中显式勾选相应高度。

#### 高度如何改变

由逻辑状态机或技能的逻辑帧时间轴在模拟步开始前设置当前高度。例如一次跳跃可配置为“地面阶段 1 → 起跳低空阶段 2 → 高空阶段 3 → 下降低空阶段 2 → 落地 1”；具体阶段由动作逻辑定义，无须按每帧视觉 Y 反算。视觉高度曲线单独驱动表现。

首版只增加离散阶段，不自动生成米制分界或强制每次跳跃经过全部三档。攻击也可在不同有效帧切换覆盖集合。权威状态、阶段推进和高度变更帧需可记录/回放；后续若接入帧同步，所有端消费相同逻辑输入。

高度集合改变时，即使 XZ 姿态和 AABB 未变，也须重新应用过滤并结算本帧配对。二维索引位置可保持不动；如果将来在树节点/格中缓存高度摘要，摘要也必须同步更新。双方二维形状仍相交但高度已不匹配时，持续接触结束并产生一次 Exit；再次匹配后按集合结果产生 Enter。技能是否可以重复伤害仍由技能命中记录控制，不能仅依靠几何 Enter 防重复。

#### 复合体与公共过滤的位置

复合体可用全部子形状高度集合的按位或作为对象级保守过滤；最终在实际子形状对级再次匹配高度。例如身体子形状只占 1 档、头部子形状只占 2 档时，整体集合为 1、2；2 档攻击命中身体区域也不能因整体集合匹配而误判命中头部。

流水线为“二维粗筛候选 → 类别/可选区域规则 → 整体高度集合 → 真实 AABB → 子形状高度集合和二维精筛”。松散四叉树与空间哈希使用相同过滤实现，首版可在候选之后以常数次位运算提前排除不兼容对象，节省后续精筛。实际收益取决于高度不匹配比例，需按阶段计时验证。

#### 楼层与适用边界

逻辑高度与所在楼层分别表达。桥上和桥下的角色可以都处于“1 地面”，在需要隔离上下区域的地图中额外使用区域/楼层交互规则；三档逻辑高度不承担跨楼层隔离。首版地图若没有此需求，可暂不增加楼层字段。

该方案的最终判定是“二维形状 + 离散高度兼容性”，适用于明确采用此玩法模型的游戏。它不承诺连续高度中的厘米级差别，也不自动提供任意三维形状相交或高速连续检测。

2D 游戏可把有效形状默认设为全高度，复用相同流水线；若 2D 游戏也有地面/空中机制，则继续使用三档。显示 Z 深度不自动参与逻辑高度。

### 7.2 射线和线段查询

拟单独实现“索引收集候选 + 共用形状精确求交”，两种粗筛返回同语义命中。首版查询阶段先支持 Circle/AABB/OBB，再扩展其他类型。

明确射线方向非零、有限最大距离、是否返回起点内部命中，以及最近命中/全部命中的差别。建议归一化方向，使距离字段是实际距离；归一化定点误差按契约验证。最近距离相同按稳定句柄及子形状 ID 决定次序。线段可表达为有限范围查询，但共线和端点语义需要专门测试。

即使索引已经按 AABB 给出最近候选，也必须真实形状求交后才能决定最终最近命中；先遇到的包围盒不保证拥有最近真实命中。系统射线返回命中点、距离和对象/子形状身份，不能沿用只返回 Bounds 命中的实现。

### 7.3 后续能力

凸多边形若有需求，可补齐顶点合法性、凸性与绕序校验、世界顶点/AABB 缓存和相应配对算法；凹形先分解为已支持的凸子形状。Capsule 等形状需同时增加定义、世界准备、宽相包围体、全部目标配对、查询与测试。

高速穿越需要独立的连续检测或有证明的分步方案。扫掠包围盒只能提供运动候选，不能把帧末布尔重叠当作连续精筛；任意旋转时起止 AABB 并集也未必覆盖中间姿态。该能力后续单独验收。

### 9.1 重点测试

- **几何边界：** 分离、相切、包含、同心、圆在矩形内、仅斜轴分离、近似平行 OBB、极小合法尺寸、数值上限和拒绝输入。
- **变换回归：** 父级转 90° 的偏移子圆；相同形状不同实例角度；只旋转不平移；第二子形状在第一子形状范围外；局部框旋转后走 OBB 精筛。
- **数值：** 独立手算标准向量；远离边界的随机用例与独立高精度/浮点参考比较；临界边界以定义的定点规则及宽整数期望验证。原参考项目不作为唯一正确性裁判。
- **流水线：** 暴力候选与两种粗筛分别接同一精筛，比较真实配对集合；该项验证粗筛完整性，精筛正确性仍由独立几何测试验证。
- **生命周期：** 两对象静止后持续 Stay；分离后一次 Exit；删除/禁用、ID 复用、回调中请求修改、掩码/高度改变、多个世界并存。
- **逻辑高度：** 三个单档与七种有效集合的匹配；攻击多选与角色单选；仅高度变化的 Enter/Exit；复合体整体集合允许但实际子形状高度不匹配；2D 全高度默认；同高度不同楼层按区域规则处理。
- **可复现性：** 固定输入及随机种子，改变注册顺序、索引后端和候选遍历顺序后，排序后的结果一致；回放按原始值验证，跨平台结果留待目标平台实测。
- **性能：** 准备世界几何、更新索引、生成候选、精筛和事件分别计时，统计子配对数、精筛次数、P50/P95、内存和 GC；固定数据与配置比较两种粗筛。

精筛 P1/P2 可先用暴力候选独立完成，再接入两种正式后端。无需等四叉树或哈希都完成才开始发现几何问题。
